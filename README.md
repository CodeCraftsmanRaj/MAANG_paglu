## 📖 Overview

**ContextForge** automatically captures, structures, secures, and retrieves your team's knowledge.

It transforms scattered knowledge—including links, files, notes, screenshots, browser activity, and AI conversations—into a structured, permission-aware knowledge base that can be consumed by humans or AI systems.

```text
 📥 CAPTURE (Automatic)          🗄️ STORE (Provenance + RBAC)          📤 RETRIEVE (Dynamic)
 ─────────────────────          ─────────────────────────────          ─────────────────────
 • Links                         • Keyword Index (Tokens)              • Explicit Scoped Search
 • Files                         • Vector Index (Bedrock Titan)        • Dynamic Inference (LLM)
 • Notes                    ──▶  • Graph Index (2-hop Walk)       ──▶  • Cited Answer Synthesis
 • Screen Watcher (OCR)          • Cryptographic Provenance            • Markdown Context Packs
 • Browser Extension             • LLM-extracted Relations
 • Watched Local Folder
```

### ✨ Key Capabilities

* 🔐 **Cryptographic provenance** for trustworthy knowledge tracking
* 🏷️ **Tag-based RBAC** for permission-scoped retrieval
* 🔎 **Three complementary indexes:** Keyword, Vector, and Graph
* 🧠 **8 dynamic retrieval paradigms** selected based on the query
* 📸 **Automatic screen capture and OCR**
* 🌐 **Browser extension** for capturing web and AI-chat context
* 📁 **Watched local folders** for automatic knowledge ingestion
* 🤖 **LLM-powered knowledge extraction and synthesis**
* 📝 **Cited answers and Markdown context packs**
* ☁️ **AWS-native production deployment**
* 🔄 **Modular provider architecture** for local and cloud deployments

# 🧩 2. Install the Browser Extension

The ContextForge browser extension automatically captures context from supported sources such as:

* Notion
* GitHub
* AI chats
* Other supported browser content

The extension can be loaded directly from the repository without requiring installation from a browser extension store.

### Installation

1. Open **Google Chrome**, **Brave**, or **Microsoft Edge**.

2. Navigate to:

   `chrome://extensions/`

3. Enable **Developer mode**.

4. Click **Load unpacked**.

5. Select the `extension/` directory from this repository.

6. Open the ContextForge Web UI.

7. Navigate to **Capture**.

8. Click **Copy session token**.

9. Open the ContextForge extension's **Options** page.

10. Paste the following values:

* **Bearer Token:** Your copied session token
* **API URL:** The URL of the ContextForge backend

11. Save the configuration.

The extension can now authenticate with ContextForge and send captured context to the backend.

# 🏗️ 3. Modular Provider Architecture

ContextForge uses an environment-driven provider architecture, allowing infrastructure components to be swapped without changing application code.

| Component                             | Local / Development Provider | Production AWS Provider        |
| ------------------------------------- | ---------------------------- | ------------------------------ |
| **LLM** (`LLM_PROVIDER`)              | Groq — Llama 3.3 70B         | AWS Bedrock — Claude           |
| **Embeddings** (`EMBEDDING_PROVIDER`) | FastEmbed — BGE-Small        | AWS Bedrock — Amazon Titan     |
| **Fact Repository** (`DB_PROVIDER`)   | SQLite (`contextforge2.db`)  | DynamoDB — Single-table design |
| **Hosting & API**                     | Uvicorn + FastAPI            | AWS Lambda + Mangum            |

This architecture allows developers to run ContextForge locally using lightweight providers while production deployments can use managed AWS services.

# 🔒 4. Authentication and "Viewing As"

ContextForge provides authentication and tag-based authorization at the knowledge-retrieval layer.

### First User Is Admin

The first registered account automatically becomes an **admin**.

Subsequent accounts are created as **members** and initially have no knowledge-access scope until an administrator assigns the appropriate permissions.

### Tag-Based RBAC

Access is controlled through tags assigned to roles.

Every search request is filtered against the authenticated user's allowed tags **on the server side**.

Authorization is applied consistently across all three indexes:

* 🔎 Keyword Index
* 🧠 Vector Index
* 🕸️ Graph Index

This prevents users from retrieving knowledge that falls outside their assigned scope.

### Viewing As

Administrators can preview the knowledge available to another role using **Viewing As**.

The selected role is securely passed through the:

```text
X-View-As
```

request header.

This allows administrators to verify role-specific visibility without changing the underlying user's permissions.

# 🧠 5. Knowledge Retrieval

ContextForge combines multiple retrieval strategies instead of relying on a single search mechanism.

### Keyword Retrieval

Uses token-based indexing for direct lexical matches.

Useful when the user knows specific:

* Names
* Terms
* Identifiers
* Technologies
* Keywords

### Vector Retrieval

Uses semantic embeddings to identify conceptually related information.

The production deployment uses **Amazon Bedrock Titan embeddings**.

### Graph Retrieval

Knowledge is represented as relationships between entities and facts.

ContextForge can perform a **2-hop graph walk** to discover related information beyond direct keyword or semantic matches.

### Dynamic Retrieval

The system can dynamically determine which retrieval strategy or combination of strategies is appropriate for a query.

The resulting context is then passed to the LLM for answer synthesis.

# 📚 6. Provenance and Knowledge Representation

ContextForge does not simply store raw documents.

Captured information is transformed into structured knowledge containing:

* Sources
* Facts
* Entities
* Relationships
* Tags
* Permissions
* Provenance metadata

LLM-based extraction identifies atomic relationships and facts from captured content.

This allows retrieved answers to remain connected to the underlying source material.

# 💻 7. Run Locally — Developer Setup

## Prerequisites

Make sure you have:

* **Python 3.10+**
* **Node.js 18+**
* **uv**
* **npm**

## 7.1 Backend

Navigate to the backend directory:

```bash
cd backend
```

Create the local environment configuration:

```bash
cp .env.local .env
```

The default local configuration uses:

* Groq
* FastEmbed
* SQLite

Install the Python dependencies:

```bash
uv pip install -r requirements.txt
```

Start the API:

```bash
uv run main.py
```

The backend will be available at:

```text
http://127.0.0.1:8000
```

# 🔐 9. Security Model

ContextForge applies authorization before knowledge is returned to the user.

The retrieval pipeline follows the general flow:

```text
User Request
     │
     ▼
Authentication
     │
     ▼
Resolve User / Role
     │
     ▼
Resolve Allowed Tags
     │
     ▼
Apply Server-Side Scope
     │
     ├──────────────┬──────────────┐
     ▼              ▼              ▼
  Keyword         Vector         Graph
   Index           Index          Index
     │              │              │
     └──────────────┴──────────────┘
                    │
                    ▼
             Retrieved Context
                    │
                    ▼
             LLM Synthesis
                    │
                    ▼
            Cited Final Answer
```

This ensures that retrieval is permission-aware rather than relying solely on the client to hide unauthorized information.
